# Organisation sealed secrets
Encrypted manifests generated by the sealing tools live under `k8s/<namespace>/<name>.sealed.yaml`.
The export ships no sealed blobs or certificates. Example documents are documentation only.

## Interface
The Sealed Secrets controller decrypts strict-scope manifests into native Secrets.
## Configuration
Namespace and Secret names must match the consuming component's `secrets.required.yaml`.
## Secrets
Only encrypted manifests belong here; plaintext and controller private keys never enter git.
## Deploy
Run `platform/sealed-secrets/seal.sh` from a terminal and review the encrypted result.
An adopting organisation must arrange a manual-sync Argo Application for these manifests;
keep its policy separate from workload applications.
## Verify
Confirm name, namespace and key names before a platform admin performs a throwaway seal/decrypt check.
## Rollback
Restore a prior encrypted manifest only while its credential and sealing key remain valid.
## Security notes
Rotate the upstream credential and re-seal each consumer namespace. A rename or cluster migration
requires re-sealing. Back up controller keys to an encrypted offline store outside git.
