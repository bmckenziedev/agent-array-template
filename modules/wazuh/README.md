# Module: wazuh (optional)

Wazuh manager, indexer, dashboard and host agents provide host and Kubernetes audit
signals. The optional module retains the pinned 4.14.8 upstream overlay, removes
demo credentials and public Services, and supplies organization audit rules.

## Interface

Agents send events/enrollment to manager ports 1514/1515; the dashboard calls its
API on 55000 and the indexer on 9200. The rendered manager overlay mounts the
`wazuh-organization-audit` ConfigMap at its local rule directory. Audit JSON uses
Wazuh's built-in JSON decoder; no custom decoder is necessary. Local IDs
100800â€“100819 are reserved: 100809 is user-session exec/attach, 100810 is break-glass
group use, 100811 is an API audit annotation containing a break-glass ticket.

The audit policy must retain ResponseStarted for streaming requests and record
metadata only. Platform audit collection must forward records into the Wazuh input
using [wazuh-agent-localfile.xml](audit/wazuh-agent-localfile.xml). The base agent
does not mount the k3s server directory; a control-plane-only, narrow audit-file
mount or a metadata-only forwarding service must be reviewed separately. Pod
annotations do not automatically become API audit annotations; the exec guard or
audit middleware must stamp the ticket. Group-array decoding and the rule hierarchy
need a vendor logtest against synthetic events before activation.

## Configuration

`modules.wazuh.enabled` defaults false; `psa_version` defaults latest and can be pinned
to a Kubernetes minor version. These flatten to M_WAZUH_ENABLED/M_WAZUH_PSA_VERSION.
`upstream_commit` documents the fixed source
commit `2c2d13c550248b1fe91a5c3e3671de06a6180769`; upgrades require changing the
install guard, overlay digests and this default together. The namespace is
PROJECT_NAME-wazuh. Storage uses STORAGE_CLASS_DEFAULT; server placement uses
LABEL_PREFIX/role-control-plane. The cluster supplies API endpoint and Kubernetes
PSA-version values. The upstream single-indexer/master topology is not HA.

## Secrets

[secrets.required.yaml](secrets.required.yaml) lists indexer-cred, dashboard-cred,
wazuh-api-cred, wazuh-authd-pass and wazuh-cluster-key. Provision fresh TLS assets
and internal_users.yml outside the repository using the upstream PKI procedure.
Remove unused upstream demo users and reconcile bcrypt hashes with the mounted
credentials. Certificate Secrets generated by the upstream deployment must also be
reviewed before applying; the server validation guard refuses any Secret documents.

## Deploy

Render with the module enabled. Manually fetch the pinned upstream commit into
an external workspace and supply its expected certificate assets. Set
WAZUH_UPSTREAM, WAZUH_INTERNAL_USERS and WAZUH_NAMESPACE. Review the rendered overlay
and run `bash modules/wazuh/install.sh --yes` only after the credential and PKI
prerequisites are complete. It renders outside the repository, validates pins,
ClusterIP and privilege boundaries, server-dry-runs, then applies. Upstream fetch
and `python modules/wazuh/render_server.py --fetch` are manual/network-dependent checks.
Provision the module namespace before its Secrets; platform namespaces are not
declared by this module. Apply the audit ConfigMap before starting the manager.

## Verify

```bash
python -B -m unittest discover -s modules/wazuh/tests -t modules/wazuh
```

Offline checks port the positive/negative policy matrix, restricted host mounts,
local entrypoint reconstruction, remote-command refusal, PSA and image pins. Audit
tests cover local ID uniqueness and synthetic tenant/break-glass event fields.
They do not prove Wazuh decoder execution. Live checks must verify upstream render,
PKI, enrollment, audit logtest, manager restart and actual CNI policy enforcement.

## Rollback

Restore previously saved non-secret workloads and policy manifests; revert desired
rendered files. Retain indexer/manager PVCs and host agent keys. Changing indexer
credentials requires the upstream security administration procedure; editing the
initial configuration does not rotate an initialized security index.

## Security notes

Known gaps: the stock agent runs as root with a small capability set, and DAC/group
access to host logs varies across Ubuntu/Debian installations. Neither DAC_OVERRIDE
nor DAC_READ_SEARCH is granted. Host binaries/logs are read-only; login directories,
SSH keys and k3s credentials are absent. Agent identity uses a narrow persistent
client.keys subPath; no detached persistence loop runs. Writable image runtime
directories prevent a fully read-only root filesystem with the stock image.

The boundary policy is a starting point: restricted CTI-feed egress, portal ingress
and upstream initialization traffic require explicit review. Standard NetworkPolicy
does not constrain node-originated traffic or override other selecting allows.
API endpoint egress is preserved, though agents do not mount API credentials.
Do not claim this policy or root/DAC behavior fully hardened until live validation.

The files under `rendered/files/modules/wazuh/overlay/` are strategic-merge and
removal fragments, not standalone Kubernetes objects. Kustomization also consumes
external pinned upstream workloads and privately generated TLS/bcrypt assets.
Applying fragments directly would create incomplete workloads or demo Secret
stubs. `tools/ci/rendered_assets.py` validates exact file/kind/name/fragment shapes;
unknown resources under files remain errors. The installer assembles and validates
the final manifests before server dry-run. Namespace patches and the standalone
namespace both prohibit Argo prune/delete. This external assembly remains manual;
only the ordinary manifests under k8s are managed by template GitOps.

Rules 100812 and 100813 alert on the native VAP validation-failure audit annotation
and break-glass streaming exec/attach/portforward activity, respectively. VAP Audit
success HTTP status does not suppress an alert. Test the built-in JSON decoder
against both successful and refused synthetic events before deployment.
